1. 프로젝트 개요

프로젝트명NewsSignal AI — 뉴스 기반 주식 호재·악재 분석 대시보드
프로젝트 기간2026년 6월 8일 ~ 2026년 6월 16일
한 줄 정의"10분마다 뉴스를 모아 유사한 것끼리 묶고, 묶음당 대표 1건만 LLM으로 호재/악재를 판정해 전체에 전파한 뒤, 섹터·종목·증시 지표와 함께 대시보드로 보여주는 수집–분석–표출 분리형 파이프라인"

1.1 프로젝트 목적 · 목표

목적. 매일 쏟아지는 증시·경제 뉴스를 사람이 일일이 읽지 않고도, 어떤 이슈가 어떤 종목·섹터에 호재인지 악재인지를 AI가 자동 분류·요약해 한 화면에서 파악하도록 한다. 투자 스터디·시장 모니터링·리서치 등 사내 활용을 염두에 둔다.

목표. 흩어진 뉴스를 빠르게 종목별 투자 인사이트로 — 매일 쏟아지는 뉴스를 누구나 5분 안에 투자 판단으로 연결한다.

  • 정보 탐색 시간 단축 — 수많은 뉴스를 직접 찾아 읽을 필요 없이 핵심만 요약 제공, 중복 기사 제거로 꼭 봐야 할 뉴스만 선별.
  • 즉각적인 판단 근거 — 종목별 호재·악재·영향도를 점수로 제시, 관련 종목·섹터를 자동 연결해 별도 검색 없이 판단.

1.2 배경 및 필요성

  • 수많은 뉴스, 개인 확인의 한계. 뉴스·공시·정책·환율·금리·원자재 등 다양한 이슈가 종목 주가에 영향을 주는데, 개인이 매일 쏟아지는 뉴스를 직접 확인하고 종목과 연결해 분석하기엔 많은 시간이 소요된다.
  • 직관적 투자 시그널 제공. 수집된 뉴스를 AI가 실시간 분석하여 호재·악재·중립 및 영향도 점수를 제공함으로써 투자의 직관적 의사결정을 지원한다.
  • 반복 모니터링 업무 자동화. 뉴스 수집·중복 제거·요약·감성 분석·시장 동향 판단을 자동화하고, 관련 종목을 KIS(한국투자증권)·DART(금융감독원 전자공시) API와 연계 매핑까지 자동 처리하여 시장 모니터링 효율을 높인다.

1.3 핵심 설계 원칙

① 뉴스를 건건이 분석하지 않고 유사 그룹의 대표 1건만 분석해 LLM 비용을 최소화한다. ② 외부 API(시세·차트·기업정보)는 DB에 적재하지 않고 실시간 호출 + 메모리 캐시로 처리한다. ③ JDK8·순수 Servlet/JSP·Tomcat·MariaDB라는 경량·고정 스택을 유지한다.

4. 주요 기능

4.1 뉴스 수집 (Collector)

  • 자동 수집(10분 주기). 네이버 뉴스 검색 API를 키워드별로 호출. 키워드는 상장 종목·증시·경제·사회·과학 등 주가 영향 분야로 구성.
  • 완전중복 제거. 정규화 제목 + 언론사를 SHA-256 해시(content_hash)로 만들어 동일 기사 재적재를 차단.
  • 쿼터 가드. QuotaGuard가 일일 한도(25,000) 대비 안전계수(0.8)로 호출량을 제어, 초과 시 skip.
  • 기사 본문 전문은 저장하지 않고 제목·요약·링크·발행일만 저장(약관·저장 정책).

4.2 유사 그룹화 (SimilarityService)

  • 제목을 정규화(HTML·특수문자 제거)한 뒤 단어 토큰 + 글자 바이그램 혼합 Jaccard 유사도를 계산. 바이그램으로 "삼성전자↔삼성", "HBM3E↔HBM" 같은 표기 차이를 흡수.
  • 판정식: (유사도 ≥ 0.12 AND 섹터 공유) OR (유사도 ≥ 0.30). 섹터가 겹치면 느슨하게, 무관하면 엄격하게 묶음.
  • 그룹마다 대표 1건과 유사 보도 수(duplicate_count)를 기록 → 이슈의 보도 규모 가중치로 활용.

4.3 AI 호재·악재 분석 (AnalyzeService)

  • 그룹 대표 1건만 LLM 호출 → 결과를 그룹 전체에 전파(비용 절감 핵심). 여러 그룹을 한 번에 보내는 배치 처리.
  • 출력은 JSON으로 강제: good_bad_type(GOOD/BAD/NEUTRAL/MIXED), impact_score(−5~+5), confidence_score(0~100), 섹터(20종 화이트리스트), 관련 종목·거시.
  • 현재 제공자는 Groq(llama-3.1-8b-instant), temperature 0.2로 판정 일관성 확보. 범위 벗어난 점수는 서버에서 clamp.
  • 현재 운영은 수동 버튼 분석(자동 분석 옵션은 60초 주기로 전환 가능).

4.4 대시보드 표출 (DashboardServlet)

  • 주요 이슈. 호재/악재/중립 헤드라인 + 더보기 목록. 기간 필터(전체·당일·전일) — 전체는 당일+전일을 날짜 균형으로 합산해 한쪽 날짜가 상위를 독식하지 않도록 함.
  • 연관 섹터 시그널. 분석된 뉴스에 등장한 섹터별 호재/중립/악재 건수(중복 보도 가중)와 영향도 평균.
  • 오늘의 증시 지표. 코스피·코스닥·환율·유가·금·은을 네이버 실시간(15초 폴링)으로 표시하고, 각 카드에 미니 그래프(스파크라인)로 최근 추세를 보여줌.

4.5 종목 상세 모달 (StockInfoServlet)

관련 종목을 클릭하면 기업 정보와 실시간 차트를 한 모달에서 제공.

  • 실시간 캔들차트(KIS). 1·5·10분/일/주/월 시간대, 캔들/라인 토글, 이동평균(MA5/20/60)·볼린저밴드·RSI 지표(클라이언트 계산). lightweight-charts로 렌더.
  • 기업 정보(DART). 대표자·설립일·업종·주소·홈페이지 + 현재가·시총·PER·PBR·EPS·외국인지분율·52주최고.
  • 최근 재무분석(DART). 매출액·영업이익·자산/부채/자본총계를 당기/전기 비교 표로.
  • 동일 업종 비교 / 소속 섹터. 같은 업종 노출 상위 종목의 시세, 종목이 속한 섹터의 시그널.

6. 핵심 알고리즘 상세

6.1 유사도 점수 체계

특징 집합 = {2글자 이상 단어 토큰(불용어 제외)} ∪ {공백 제거 후 연속 2글자 바이그램}. 두 제목의 Jaccard = |교집합| / |합집합|. 임계값(0.12/0.30)은 설정으로 조정 가능. 의미가 아닌 표기 매칭이라, 향후 임베딩/TF-IDF 전환이 품질 개선의 핵심 레버.

6.2 호재/악재 점수 체계

LLM이 "한국 주식 애널리스트" 역할로 판단하며, 코드에는 채점 수식이 없다(자유 판단 + 형식·범위만 강제). impact_score의 부호=방향, 절댓값=강도. 대시보드는 ① 이슈 정렬에 절댓값(ABS(impact_score))을 1차 키로, ② 섹터 분위기에 평균(AVG)을, ③ 동점 시 보도 수(duplicate_count)를 사용.

6.3 섹터-종목 매핑

종목 시세 표·동일업종 비교는 stock_master.industry(KRX 표준 업종분류, KIND에서 적재) 기반의 정적 매핑(sector_stock_map)에서 온다. 업종분류가 투자 테마와 완전히 일치하지 않아(예: 태양광이 '반도체 제조업'으로 분류), 잡음 종목을 정제하는 작업을 병행했다.

7. 개발 과정의 주요 문제와 해결

실데이터·실운영에서 드러난 문제들을 진단·수정한 과정이 이 프로젝트의 상당 부분을 차지한다.

7.1 LLM 제공자 전환과 비용·한도

초기 Gemini는 무료 일일 한도(RPD)가 작아 대량 분석에 부적합했다. 로컬 Ollama(무한·무료)를 거쳐, 최종적으로 Groq(8B, 무료·고속)로 안착. Groq는 Cloudflare 뒤에 있어 Java 기본 User-Agent가 403(error 1010)으로 차단되는 문제를 User-Agent: Mozilla/5.0 지정으로 해결. 모델별 토큰 한도(TPD/TPM)에 맞춰 입력 길이를 줄이고 배치·재시도(429 대기) 로직을 추가.

7.2 KIS 시세 토큰 안정화

종목 시세에서 거래량·거래대금·시총이 0↔정상으로 깜빡이는 현상의 원인은 KIS 인증 실패 시 네이버 폴백(해당 필드 없음)으로 떨어지는 것이었다. 근본 원인은 ① 동시 다발 토큰 발급(EGW00133), ② 초당 호출 초과(EGW00201), ③ 만료 토큰 미감지(EGW00123). 해결: 토큰 디스크 영속화 + 이중검사 락 + 글로벌 throttle + 만료 감지 시 자가 재발급·재시도로 자가치유하도록 구현. 결과적으로 재기동 후에도 안정적으로 실값 반환.

7.3 섹터 데이터 정합성(거짓 양성) 정제

"금·은·유가"처럼 짧은 섹터명이 본문 단순 포함으로 무관 기사(은행·현금 등)까지 매핑되어 섹터 패널이 오염됐다. 모호 섹터를 분리해 상품 문맥이 있을 때만 인정하고, 기존 오염은 정리 SQL로 제거. 또한 "반도체 관련 종목"에 태양광·디스플레이·전자부품이 섞이는 문제(KRX 업종분류 한계)를 industry='반도체 제조업'으로 좁히고 오분류 종목을 제외해 정제(232→81종목). 엔터테인먼트(통신·방송 장비 65종목 혼입) 등도 동일 방식으로 정리.

7.4 CSP로 인한 외부 스크립트 차단

보안 헤더의 Content-Security-Policy: script-src 'self' 때문에 CDN의 차트 라이브러리가 브라우저에서 차단되어 차트가 안 떴다. CSP를 완화하지 않고 lightweight-charts를 로컬에 번들(동일 출처)해 해결 — 보안 정책 유지.

7.5 배포·환경 관련 함정

  • 전개 디렉토리 재전개. WAR만 교체하고 catalina만 재기동하면 기존 전개본이 남아 구버전이 동작 → WAR 복사 후 전개 디렉토리를 삭제해 재전개 강제.
  • 한글 문자셋. PowerShell 파이프로 한글 SQL을 넘기면 깨져 정규식 오류 발생 → UTF-8 파일 + cmd 바이트 리다이렉션으로 주입.
  • 형제 프로젝트 충돌. 동일 Tomcat의 sibling /newssignal 재배포가 공유 DB 설정을 리셋·섹터를 재오염 → 비활성 유지.
  • 기동 순서. MariaDB가 먼저 떠 있어야 커넥션 풀 초기화 성공(아니면 컨텍스트 404).

8. 보안

  • 모든 DB 접근 PreparedStatement(SQL Injection 방지), 출력 escape(XSS 방지).
  • 상태변경 POST는 CSRF 토큰 검증(CsrfFilter), 토큰은 세션·메타 태그로 전달.
  • CSP(script-src 'self') 등 보안 헤더 적용(SecurityHeaderFilter).
  • 외부 API 키는 환경변수로만 관리, 로그·예외·프론트에 미노출. 기사 본문 전문 미저장.

9. 성과 및 한계

성과. 뉴스 수집부터 AI 분석, 시세·차트·기업정보 실시간 연동, 대시보드 표출까지 전 구간이 동작하는 운영 가능 수준에 도달. 그룹 대표 1건 분석·메모리 캐싱으로 비용·외부 호출을 최소화.

한계. ① 유사도가 의미 기반이 아닌 표기 매칭이라 반대 의미 뉴스가 묶일 수 있음. ② 호재/악재 판정에 명시적 채점 기준이 없어 모델 성능에 의존. ③ 섹터-종목 매핑이 KRX 업종분류라 테마와 불일치 가능. ④ 분석이 수동 버튼이라 신선도 관리 필요. ⑤ API 키 평문 보관 등 운영 보안 보강 필요.
